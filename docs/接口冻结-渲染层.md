> 目的：让 4 个智能体各写一组**互不重叠**的文件，同时保证拼起来能跑。

## 1. 数据模型（唯一真相）

旧版 **56 个页签定义**（`TABS` 54 ＋ 编辑器 ＋ 内部数据表《地图》）里 **34 个是数据驱动的**（form 9 / card 6 / table 18＋1），它们共用一张表：

```
settings_entities（新库已存在）
  id, workspace_id, project_id, schema_template_id, name, values(JSON), order_key, revision, deleted, ...
```

对应关系（**不要发明第二套模型**）：

| 页签类型 | 一条 `settings_entities` 记录 = | `schema_template_id` | 关键点 |
|---|---|---|---|
| `table` | 表格里的**一行** | 该页签 `tab.id` | `values[列.name]` 就是单元格值 |
| `card` | 卡片列表里的**一张卡** | 该页签 `tab.id` | `name` 是卡标题，其余字段在 `values` |
| `form` | 该页签的**唯一一份记录** | 该页签 `tab.id` | 全页签只有一条（如「世界基底」） |

- **`values` 的键就是 `TabDef.columns[].name` / `TabDef.modules[].fields[].name`（中文键）**，渲染层不得改名、不得翻译、不得套一层英文别名。
- `order_key`：行/卡顺序，新建时由持久化层生成（调用方**不传**）。
- `name`：表格/卡片的主标题列（`displayCol` 指定的列若存在，用它的值做展示名；写回时同步 `name`）。

### IPC 通道（W6 / settings-bot 交付，渲染层按此调用）

```ts
listSettingsEntities({ context, projectId?, schemaTemplateId?, includeDeleted? })
  -> { entities: SettingsEntity[] }
getSettingsEntity({ context, entityId })
  -> { entity: SettingsEntity }
saveSettingsEntity({ context, entityId?, projectId, schemaTemplateId, name, values, orderKey? })
  -> { entityId, revision, orderKey }
```

契约类型与错误码在 `packages/contracts/src/commands/index.ts` 与 `errors.ts`（闭集，禁止自造码）。
`context` 形状：读 `{ requestId, workspaceId }`，写 `{ requestId, workspaceId, projectId, expectedRevision }`。

## 2. 冻结的元数据类型（`@yfe/schema-tabs`，W1 交付）

15 个导出符号（`packages/schema-tabs/src/types.ts`）：

```ts
type FormField      = { name: string; desc: string; example: string; kind?: 'numeric' }
type FormModule     = { name: string; fields: FormField[] }
type TableColumnType = 'text'|'select'|'date'|'number'|'textarea'|'calendar'|'character'|'characters'|'tableRef'
type TableColumn    = { name: string; type?: TableColumnType; options?: string[]; width?: string; tip?: string;
                        calendar?: boolean; refTab?: string; refCol?: string; hidden?: boolean; fixedOptions?: boolean }
type TabType        = 26 个字面量（'editor'|'form'|'table'|'card'|'map'|'canvas'|'worlds'|'tavern-*'|…）
type TabDef         = { id; name; group; type: TabType; description; modules?: FormModule[]; columns?: TableColumn[];
                        tips?: string[]; displayCol?: string; subtitleCol?: string; codeRule?: string; newestFirst?: boolean }
type TabGroup       = '工作面板'|'正文写作'|'灵感工具'|'开书定位'|'角色管理'|'世界构建'|'大纲规划'|'酒馆模式'|'创作管理'|'运营维护'
type GenrePack      = 10 个中文题材包名
type ProjectType    = 'full'|'custom'
type VisCtx         = { type: ProjectType; features: string[]; pack?: GenrePack }
type FeatureTier    = 'locked'|'default'|'optional'
type VolumeLike     = { id: string; title: string }
const GROUPS: string[]        // 10 项，顺序＝旧版侧栏顺序
const GENRE_PACKS             // as const，10 项
const DEFAULT_PACK: GenrePack = '东方修真'
```

### 三条硬约定

1. **六个页签的属性是 getter**：`worldbase` / `power` / `politics` / `economy` / `belief` / `justice` 的
   `name` / `description` / `modules` / `tips` 读的是**当前题材包**。消费方必须走属性读（`tab.modules`），
   **禁止**展开成普通字段、**禁止**把序列化快照长持——切题材包后要重新读。
2. **`TableColumn.hidden`（`cH()` 产物）＝保留数据但不渲染该列**；列 `name` 是存储键，不得改写。
3. **`TabDef.type` 决定渲染器**：`form`/`card`/`table` 三个走通用渲染器（9＋6＋18＝33 个侧栏页签，再加不在侧栏的《地图》共 34 个）；
   其余 22 个是专属面板（含 `editor`、`map`/`worlds`/`canvas`、`tavern-*` 八个、`guide`/`inspire`/`about` 等）。
   > 🔴 统计口径：以**移植后的 `TABS` 数组**为准（`TABS.length === 54`）。静态 grep `type: 'form'` 只能数到 5，
   > 制度四页签 `politics`/`economy`/`belief`/`justice` 由 `part1.ts` 的 `...INSTITUTION_TABS.map(institutionTab)` 运行时展开，
   > 静态数不到 —— 于是会得出「5/6/18＋23」这种少 5 个的错误分布（迁移矩阵与初版计划书都曾这么算）。

## 3. 三个通用渲染器的组件契约（W2 / W3 / W4）

共同要求（三个组件都适用）：

- **纯展示 + 事件**：不直接调用 IPC、不 import `@yfe/client-sdk`、不 import `node:*`。
  数据由 props 进、用户意图由 emits 出；落库由外壳（W5）调 `app-state`。
- 每个交互元素带 `data-testid`（供挂载测试与真窗口 `--gui-check` 使用）。
- 中文文案只来自 `TabDef`（`name`/`description`/`tips`/`codeRule`/列选项），**不得在组件里另写一份**。
- 空态、只读态、超长内容截断都要处理；不引入新依赖（已有 `vue`、`@yfe/ui`、`@vue/test-utils`、`happy-dom`）。
- 测试：`// @vitest-environment happy-dom` + `@vue/test-utils` 挂载测试。

### W2 — 表单渲染器（9 个 form 页签：5 个静态 ＋ 4 个制度页签由 `INSTITUTION_TABS` 运行时展开）

文件：`apps/desktop/src/renderer/schema/TabFormView.vue`、`apps/desktop/src/renderer/schema/schema-form.ts`、
`apps/desktop/tests/schema-form.test.ts`、`apps/desktop/tests/tab-form-view.test.ts`

```ts
// TabFormView
props:  { tab: TabDef; value: Readonly<Record<string, unknown>>; readonly?: boolean; busy?: boolean }
emits:  { 'update:value': [Record<string, unknown>]; save: [Record<string, unknown>] }
```

`schema-form.ts` 导出纯函数：`readFormValues(tab, value)`（按 `modules[].fields` 顺序给默认值）、
`applyFieldInput(value, field, raw)`（`kind:'numeric'` 只留数字）、`formDirtyState(value, saved)`、
`orderedFields(tab)`。**必须**按 `modules` 分组渲染并在每组渲染标题 `module.name`。

### W3 — 表格渲染器（18 个 table 页签）

文件：`apps/desktop/src/renderer/schema/TabTableView.vue`、`apps/desktop/src/renderer/schema/schema-table.ts`、
`apps/desktop/tests/schema-table.test.ts`、`apps/desktop/tests/tab-table-view.test.ts`

```ts
// TabTableView
props:  { tab: TabDef; rows: readonly SettingsEntity[]; readonly?: boolean; busy?: boolean }
emits:  { create: []; update: [SettingsEntityId, Record<string, unknown>]; delete: [SettingsEntityId];
          reorder: [SettingsEntityId, SettingsEntityId | null] }
```

`schema-table.ts` 导出纯函数：`visibleColumns(tab)`（过滤 `hidden`）、`cellText(column, row)`（按 type 格式化：
数字/日期/`characters` 顿号连接/`tableRef` 用引用名）、`editableCell(column)`、`sortRows(tab, rows)`
（`newestFirst` 取反）、`nextRowName(tab, rows)`。
**`tableRef` 列**：只读展示引用名 + 「选择」按钮 emit `update`，选择器本身由外壳提供（W5 传入 `refOptions?: (column) => {id,label}[]` 可选 prop，缺省时该列只读）。
行内编辑用 `<input>/<select>/<textarea>`（`type:'select'` 且有 `options` 时用 select；`fixedOptions` 时禁止自定义值）。

### W4 — 卡片渲染器（6 个 card 页签）

文件：`apps/desktop/src/renderer/schema/TabCardView.vue`、`apps/desktop/src/renderer/schema/schema-card.ts`、
`apps/desktop/tests/schema-card.test.ts`、`apps/desktop/tests/tab-card-view.test.ts`

```ts
// TabCardView
props:  { tab: TabDef; cards: readonly SettingsEntity[]; selectedId?: string | null; readonly?: boolean; busy?: boolean }
emits:  { select: [SettingsEntityId]; create: []; update: [SettingsEntityId, Record<string, unknown>];
          delete: [SettingsEntityId] }
```

`schema-card.ts` 导出纯函数：`cardTitle(tab, card)`（`displayCol` → `subtitleCol` → `name` 的优先级）、
`cardSubtitle(tab, card)`、`cardFields(tab)`（卡片详情要展示的列，排除 `hidden`）、`gridColumns(tab)`
（按 2–4 列自适应，依据 `columns[].width` 是否缺失）。

## 6. 纪律（违反即回滚）

1. **测试串行**：跑测试前 `node tools/test-lock.mjs acquire <owner> "<说明>"`，exit 0 才跑，跑完立刻 `release`；
   返回 **exit 2** 表示别人持锁 → 等 20–30 秒重试，**绝不删 `.test-lock`**。持锁期间不要做长时间重构。
2. 仓库禁止 `as any` / `@ts-ignore` / `@ts-expect-error`（当前 0 命中，保持 0）。
3. 测试定位文件用 `fileURLToPath(new URL('.', import.meta.url))`，**不要** `import.meta.dirname`。
4. `tsc` 输出带 ANSI：`Select-String "error TS"` 前先 `-replace "\x1b\[[0-9;]*m",""`。
5. vitest 4 不接受 `--reporter=basic`；长命令重定向到 `_scratch/logs/*.log` 再过滤；
   **不要**用 `Select-Object -First N` 截管道（会杀进程并返回 -1）。
6. 只跑自己的测试文件：`npx vitest run --project desktop tests/<自己的文件>.test.ts`。
