# 部署与运维设计

## 交付形态

桌面安装后直接离线使用，无需安装 Node、Docker 或数据库。Android 安装签名 APK 后可本地写草稿。只有统一设备管理、远程控制和中心同步需要后端。文件直连可单独配置，不能强制所有用户配置 Cloudflare。

后端发布项目官方版本镜像与 Compose，linux/amd64、linux/arm64 分架构构建。首版一个服务包含 API、Web 管理端、SQLite、内部队列与可信插件；反向代理可选，不要求 Redis。镜像仓库地址在实际发布时确定，不在文档中伪造已存在的镜像。

## 容器路径与配置

| 路径 | 用途 | 要求 |
| --- | --- | --- |
| /data/db | SQLite、WAL、迁移状态 | 本机可靠持久卷，不是客户端远程 SMB/NFS |
| /data/assets | 附件与上传暂存 | 可在 NAS 本机共享目录绑定；验证权限与磁盘 |
| /data/plugins | 插件清单、可信包与插件数据 | 版本与校验；同步包不自动执行 |
| /data/backups | 一致备份与附件清单 | 独立备份策略，至少另有一个故障域副本 |
| /imports | 管理员选择的素材根目录 | 默认只读，导入经过校验 |
| /run/secrets | 主密钥等秘密文件 | 只读、限制宿主权限，不进镜像 |
| /tmp | 临时文件 | 容量受限，不能保存唯一持久数据 |

数据库与附件可以分别挂载。fnOS NAS 自己的本机磁盘目录可用于数据库；远程挂载目录不作为 SQLite 在线卷。配置路径必须可写性检查通过，启动失败不能创建另一个临时空库继续运行。

## Compose 目标示例

以下是后端实现后的交付模板设计，镜像与其中的环境变量尚需按 P3 实现，当前不能用于启动本仓库旧版。实际发布必须同时提供版本化 compose 文件、env 示例与升级说明。

```yaml
services:
  yfe-server:
    image: ${YFE_IMAGE:?设置实际发布或本地构建的版本镜像}
    restart: unless-stopped
    init: true
    user: "10001:10001"
    ports:
      - "${YFE_BIND_ADDRESS:-127.0.0.1}:${YFE_PORT:-8787}:8787"
    environment:
      NODE_ENV: production
      YFE_LISTEN_HOST: 0.0.0.0
      YFE_LISTEN_PORT: "8787"
      YFE_PUBLIC_URL: ${YFE_PUBLIC_URL:?设置用户访问的完整地址}
      YFE_DATA_DIR: /data
      YFE_LOG_LEVEL: info
      YFE_MASTER_KEY_FILE: /run/secrets/master_key
    volumes:
      - ./data:/data
      - ./master.key:/run/secrets/master_key:ro
    read_only: true
    tmpfs:
      - /tmp:size=128m,mode=1777
    cap_drop: [ALL]
    security_opt:
      - no-new-privileges:true
    stop_grace_period: 30s
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:8787/health/ready').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 30s
    logging:
      driver: json-file
      options:
        max-size: 10m
        max-file: "3"
```

宿主必须预先创建 data 与有效 master.key 文件，令 UID 10001 可访问，秘密文件限制其他用户读取；不能让 Docker 把不存在的 key 源路径创建为目录。模板 UID 可在官方支持方式下映射，服务本身不要求 root。30 秒启动宽限仅是初值，大库迁移需调整且单独展示状态。

主密钥格式在实现中固定为密码学随机生成的 32 字节、Base64 编码文本，启动时严格校验；它不是用户自选短密码。更换主密钥需要受控重加密流程，不能直接替换文件后继续使用旧密文。部署工具应生成与校验文件，用户无需手工编辑密钥内容。

127.0.0.1 默认只供本机反向代理访问。飞牛局域网部署可将 YFE_BIND_ADDRESS 配置为 NAS 局域网地址或在明确网络策略下设为 0.0.0.0；浏览器访问的是 NAS/域名，不是容器内 localhost。master_key 不是登录密码；初始化后仍需创建管理员和配对设备。

## 环境变量契约

监听参数、公开 URL、数据目录、日志、主密钥文件、允许代理、上传上限、存储驱动与任务并发均在启动时校验。未知关键变量或路径错误要报告，不能静默忽略。配置优先级为内置默认、持久非敏感配置、受支持环境变量；秘密优先文件引用，不通过日志或 Web 读接口返回。

镜像构建使用受支持 Node LTS 基础镜像并固定摘要，多阶段构建，只带 production 依赖、迁移和 Web 产物。better-sqlite3 在对应 CPU/系统 libc 下构建验证；首版优先 Debian slim 基线，不能仅为省体积换 Alpine 而跳过原生依赖验证。镜像提供版本、协议与 SBOM 信息。

## 飞牛与云端部署流程

1. 在飞牛或 Linux 创建专用持久目录与备份位置，核对 CPU 架构、磁盘和 UID/GID。
2. 获取实际版本镜像、校验摘要，准备 compose、非敏感 env 和独立秘密文件。
3. 启动后查看 ready 状态，完成一次性管理员初始化；初始化前不开放公网入口。
4. 通过 HTTPS 入口访问 Web 管理端，设置工作区、存储和备份；桌面/手机用短期配对码加入。
5. 用副本验证双向修改、断网重连、冲突与备份恢复后再迁移正式数据。

云服务器与 NAS 使用同一 API 和数据结构。云端防火墙仅开放所需 HTTPS 入口，内部服务端口不必直接暴露公网。对象存储用于附件与备份，不把活 SQLite 放进对象存储挂载层。

HTTPS 由受支持反向代理终止，SSE/大附件需配置流式转发、大小和超时，服务仅信任指定代理。Cloudflare Tunnel、VPN 或其他入口可选；代理限制、WebDAV 方法、上传大小和超时须实测，不能默认所有通道都等价。内网 HTTP 回源与用户 HTTPS 入口分别记录，避免协议和端口混用。

SMB/NFS 优先由宿主机挂载，再作为受限素材/对象根目录绑定容器，默认不使用特权挂载。公开互联网不直接开放 SMB/NFS/明文 FTP。局域网直连的权限和后端用户权限分开配置。

## 升级、备份与恢复

升级前记录当前镜像摘要、数据库版本、插件版本和配置，创建一致备份并校验可读。暂停接收新任务、完成检查点、替换镜像，执行有事务/检查点的迁移，ready 后做登录、读取、保存和同步冒烟测试。重建容器不删除持久卷；镜像内不保存唯一数据。

降级必须检测 schema 和插件数据版本。旧镜像不能直接打开更高版本库；回滚依靠升级前兼容备份和原镜像。恢复先在隔离新实例验证，再切入口，防止新旧服务同时写同一卷或同一权威同步目标。

备份集包含一致数据库、所引用附件、配置、插件包清单与密钥恢复说明；秘密另行受控保存。备份需可恢复到全新实例，比较正文、引用和摘要。定期保留与异地副本策略可配置，GC 不删除仍被恢复点引用的附件。

日志轮转、磁盘水位、任务积压、失败率、备份年龄、证书有效期和版本为运维指标。磁盘满优先停止新上传并报告，不清理未同步草稿或唯一版本。日常诊断导出默认脱敏。
