## 新发现：Electron 内嵌 Node 与系统 Node 的 SQLite 差异

Electron 内嵌 Node 为 24.21.0；系统 Node 为 24.22.0。对同一业务链路使用独立新库观察到：

1. 系统 Node 的原有保存自检通过。
2. Electron 的 `ELECTRON_RUN_AS_NODE=1` 可加载 better-sqlite3、迁移、创建作品和章节，但在 ASCII 路径新库的保存操作中，`INSERT INTO outbox` 报 `SQLITE_CANTOPEN`，事务回滚。
3. 仅给该探针子进程设置独立 ASCII TEMP/TMP，可使同一保存操作成功；使用 `temp_store=MEMORY` 的探针也能成功。这两种操作都没有解决 GUI 崩溃，不能视为 GUI 修复。
4. 将测试库放入当前含中文用户名的系统临时目录时，Electron 在打开数据库阶段即报无法打开文件。系统 Node 的相关测试没有这一现象。尚未判定是路径编码、运行时或其他宿主因素。

因此，单独调整临时存储策略不能覆盖实际用户数据目录的全部情形。已撤回试验性的 worker 设置及试验回归文件，保留上一轮已通过的项目代码，探针与失败日志全部保留。**不能再仅凭系统 Node 自检通过，就宣称 Electron 内嵌运行时的数据库链路也已通过。** 该差异需继续定位，不归因于本次重装。
