## 4. 并发开发纪律（用户硬性要求）

用户明确：**禁止同时编辑一个文件、同时运行一个测试**（m00001）。

### 4.1 写入隔离

1. **一人一目录**：每个任务在启动前登记「写入范围」（上表第 4 列），范围互不重叠。
2. **共享文件独占制**：根配置（`package.json`/`tsconfig.base.json`/`vitest.config.ts`）与 `packages/contracts/**` **只由 Lead 写**，其他人只读。需要改动时向 Lead 提请求，由 Lead 串行实施。
3. **契约冻结**：`packages/contracts` 打上 `frozen` 标记后，变更必须走 ADR + 全量回归（设计文档要求「契约变更统一评审」）。
4. **写前读**：任何文件在编辑前必须 `read` 最新版本；遇 `FS_STALE_VERSION` 重新读取后再改。

### 4.2 测试隔离

1. **包级并行、全局串行**：日常用 `npx vitest run --project <name>`（各包独立 project）。
2. **全量测试令牌制**：`npm test`（全量）同时只允许一人执行；令牌由 Lead 发放，用后即还。
3. **缓存隔离**：`VITEST_CACHE_DIR=.vitest-cache/<成员名>`，避免缓存互相污染。
4. **端口隔离**：后端服务测试使用各自端口段（Lead 分配），禁止抢占 8787/5199。

### 4.3 冲突升级路径

发现写入范围重叠 → **立即停止写入** → 向 Lead 报告 → Lead 重新划分范围或串行化 → 恢复。

## 5. 质量门禁

| 门禁 | 命令 | 通过标准 |
| --- | --- | --- |
| 类型 | `npm run typecheck` | 0 error（strict + noUncheckedIndexedAccess） |
| 测试 | `npx vitest run --project <pkg>` | 全绿；新增代码覆盖率 ≥ 分支 70% |
| 契约漂移 | 契约快照测试 | `packages/contracts` 导出面变化必须显式更新快照 |
| 保存可靠性 | 故障注入测试 | 磁盘满/只读/进程被杀/迟到回包 均不丢数据 |
| 同步可靠性 | 双客户端测试器 | 断网/重复/乱序/时钟偏差 均收敛 |

**发布门禁**（设计文档 11）：保存、同步、迁移、权限或备份恢复出现阻断缺陷 → 不发布。
