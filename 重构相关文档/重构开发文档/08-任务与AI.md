# 任务与 AI 开发设计

## 并发与任务模型

多任务与 CPU 并行分别设计。模型 HTTP、文件传输采用异步 I/O；分词、解析、向量评分和校验进入有界 worker_threads。线程不能替代持久任务、版本保护和数据库事务。[Node Worker 说明](https://nodejs.org/api/worker_threads.html)

任务包含 jobId、workspaceId、projectId、目标实体、kind、executor、不可变输入版本、配置版本、secretRef、priority、attempt、checkpoint、outputRef 和预算。任何执行代码不得完成后查询“当前作品”决定保存位置。

状态机为 queued → running → succeeded/failed/cancelled；waiting_network、waiting_confirmation、paused 是持久等待态。取消请求可经过 cancelling，只有执行器确认或租约失效处理后才能判定终态。外部调用状态不确定时进入 waiting_confirmation，而非静默重试计费。

领取任务以数据库事务设置执行租约；心跳续期，超时后先检查输出和外部请求是否可查询，再决定恢复。所有可重试副作用带幂等键；模型服务不支持幂等时不能宣称 exactly-once。UI 关闭不取消工作区全部任务，项目退出仅按用户设置处理本项目任务。

## 调度与资源

默认先限制两个交互 AI 请求，批量任务低优先级；并发由服务商配额、模型、费用和硬件共同限制。CPU 池初始最多 min(4, max(1, 可用核心数-1))，P0 实测后可调；内存不足减少池与批大小。数据库长计算不在写连接内完成。

任务队列有长度和输入大小上限，超过时排队或返回可解释错误。CPU Worker 以阶段边界检查取消，无法协作时可终止并用检查点恢复；终止 worker 不得中断未提交数据库事务。服务端与桌面均支持优雅停止。

## AI 数据流

用户选择任务 → 固定正文基线与权限 → 构建上下文 → 检查预算 → 发起流式模型请求 → 增量落输出 → 完成建议稿 → 用户采用/按已授权规则提交。生成不直接覆盖正文，采用时重新验证 expectedRevision。

统一助手入口根据选区、章节或作品展示任务模板；采样、模型路由、预算等放高级配置。任务中心统一展示目标、执行位置、状态、费用估计与错误，用户能暂停批量工作。

Provider 接口暴露能力而非只暴露 URL：流式、结构化输出、工具调用、上下文上限、取消与用量。凭据由宿主解析 secretRef，插件和界面不接收明文 Key。云模型、本机模型和后端模型分别标识，localhost 的含义不跨设备复用。

## 上下文与检索

先按工作区、作品、视角、保密级别和叙事锚点过滤，再执行关键词和向量检索，最后按预算组织证据并再次校验权限。沿用旧版可见性规则：角色视角不读取秘密字段，作者/导演按授权使用，明确排除域保持排除；迁移建立固定回归样本。

资料、摘要和索引都记录源 revision。正文修改只使相关摘要与索引失效，不在每个键入时重建全库。召回候选使用有界数量，用户能查看带入资料与来源版本，避免隐式把整库塞进提示词。

缓存键至少包含模型/Provider 配置、模板版本、输入摘要、来源 revision、权限范围与任务参数。缓存命中不绕过权限；取消或失败输出不作为完整缓存。业务摘要缓存与供应商提示词缓存分开统计，供应商能力缺失仍可运行。

## 流式与故障

UI 按帧或短时间窗口合并 Token 片段，服务按 sequence 传递；输出检查点分批持久保存，不能每 Token 写事务。断流后展示 partial 和恢复选择，不把部分输出标为成功。订阅重连查询持久 job_outputs，临时事件流不是唯一副本。

重试仅用于明确可重试故障，采用退避、抖动和次数/预算上限。身份失败、Schema 不支持与费用不足不循环重试。外部模型收到请求但本地丢失确认时提示结果不确定，避免自动重新计费。

正文同一基线可生成多个建议稿；采用任一个之后，其他建议稿再采用需重新基线比较。结构化输出先过 Schema 与业务校验，工具调用经能力代理授权，不让模型或插件直接写任意文件和数据库。

## 效率评测

固定续写、审校、人物一致性、摘要、资料整理任务集，记录原版与新版的上下文 Token、首字延迟、总时长、失败重试、费用、事实一致性和人工采用率。模型和网络保持一致后再比较架构收益。

流式渲染与检索可优化本地延迟；模型服务生成速度属于外部因素。不同模型路由、并发或多 Agent 的收益需由任务质量和费用证明，不以任务数量作为效率指标。
