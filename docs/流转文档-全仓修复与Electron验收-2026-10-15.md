## 项目类型与执行链路

这是本地优先的小说创作管理应用，使用 npm workspaces 管理共享业务包、Electron 桌面和 Fastify 后端。

| 目录或层 | 职责与约束 |
| --- | --- |
| `packages/contracts` | 命令、查询、ID、错误、同步与移动端契约 |
| `packages/domain` | 可移植领域规则 |
| `packages/application` | 应用用例、权限、幂等、事务端口；不得依赖 Electron、SQLite 驱动、DOM、Fastify |
| `packages/persistence-sqlite` | better-sqlite3、WAL、仓储、草稿事务、迁移、备份恢复 |
| `packages/client-sdk` | 客户端调用、响应信封与超时语义 |
| `packages/ui` | Vue 共享组件、保存状态文案、设计令牌 |
| `packages/plugin-sdk`、`packages/plugin-host` | 插件清单、权限与 Cordis 生命周期适配 |
| `packages/legacy-import` | 旧版数据解析、引用映射与导入 |
| `apps/desktop` | Electron main/preload、DB worker、Vue 3、CodeMirror 6 |
| `services/server` | Fastify 服务、同步、附件、事件、管理恢复 |
| `deploy` | Dockerfile、Compose；实际镜像未在本机验证 |

桌面正文链路为：CodeMirror 输入 → AppState → DraftSession → client-sdk → preload 白名单 → main 可信来源校验 → service-host → 独立 DB worker → application 用例 → SQLite 事务。数据库连接仅由 worker 持有。

当前 worker 实际使用 **child_process**，以 Electron 可执行文件加 `ELECTRON_RUN_AS_NODE=1` 运行；虽兼容 utilityProcess 通信，但没有完成宿主切换。桌面本地工作区固定为 `ws_local`，不能每次启动随机生成，否则会出现数据归属切换。

Android 选型为 uni-app x 蒸汽模式、UTS 与原生 SQLite/Room，当前主要是契约与架构约束。手机不能直接运行 Electron、CodeMirror 桌面控件或 better-sqlite3。驱动抽象和纯 DDL 导出仍有后续工作。

## Electron 排查过程与最终根因

### 重装没有改变故障

重新下载 npm 官方 electron 包和官方 GitHub Windows x64 发行包，保持 Electron 44.7.2。npm integrity 与发行包 SHA-256 校验均通过，新旧 **73 个运行文件的 SHA-256 完全一致**。

发行 zip SHA-256：`10a89447ef64ac5cb9f782af48ffd83734a40ae91681259d1048ca3c9e6c5da4`。

electron.exe SHA-256：`1f41127064012c5e74422b2e0dfc35ff0b0fe8d7908b97d01503becd1b7fa9e1`。

直接启动受影响的工作区运行时，默认退出 `0x80000003`；显式关闭沙箱时观测到 `0xffff7003` 与 Crashpad not connected。后者是 Crashpad 未连接处理器的终止状态，不能直接当作原始崩溃根因。更早历史记录还有 `0xC0000005`，不能把不同实验状态混写。

### SQLite 的表面中文路径问题是完整性权限问题

| 观察或对照 | 结果与解释 |
| --- | --- |
| 系统 Node 跑同一保存链路 | 成功；系统 Node 进程是 Medium Integrity |
| 工作区 Electron 的 Node 模式 | 部分 F 盘库能打开，但保存时 SQLite 临时文件报 CANTOPEN；用户 TEMP 下库甚至无法打开 |
| 中文与 emoji 在工作区文件、数据库中往返 | 成功，不支持“SQLite 不兼容中文”的判断 |
| Electron 下普通 node:fs 写用户 TEMP | 同样 EPERM，说明问题超出 SQLite 驱动 |
| 实际进程令牌与文件 ACL | Electron 为 Low Integrity；仓库根显式 Low，运行时继承 Low；用户目录和系统 Node 为普通 Medium |
| 仅给探针改工作区 ASCII TEMP，或 temp_store=MEMORY | 部分保存恢复，但用户目录开库和 GUI 没有完整解决；实验设置已撤回 |
| 同一官方完整 runtime 在普通用户临时目录新建文件后运行 | 恢复 Medium；中文库、WAL、中文/emoji 和 8 MiB 磁盘临时表通过 |
| 只提高工作区 electron.exe 的完整性 | --version 和 SQLite 恢复，但默认沙箱 renderer 仍崩溃；单文件调整不足 |
| 使用普通用户目录下完整运行时 | 默认沙箱 GUI 检查通过 |

已证实可执行文件 Low 标签导致主进程降权。完整运行时的干净目录对照解决了 renderer 问题，但没有进一步逐条隔离资源目录中每个 ACL 项的作用；不要据此宣称 Everyone 的 DENY(DC) 单项就是 renderer 根因。最终采用内容复制隔离继承权限，而非广泛重设仓库 ACL。

### Windows 开发启动器的持久修复

`apps/desktop/bin/dev-desktop.mjs` 调用 `electron-runtime.mjs`，对完整 dist 的相对文件名和内容计算 SHA-256，将运行时缓存到：

```text
%LOCALAPPDATA%\YouthFantasyEngine\electron-runtime\<内容摘要>\electron.exe
```

实现逐文件新建并写入字节，目录继承用户目录权限，不复制工作区安全属性。随机 staging 目录复制完成后校验、原子发布；并发发布复用完整赢家，复用前再次校验内容；拒绝符号链接和不支持的文件类型。升级运行文件会得到新摘要，不覆盖正在运行的旧缓存。

该逻辑用于源码开发启动器，其他平台直接用已安装运行时。打包安装流程尚需另行验收，不能把开发缓存当作已完成的安装包方案。缓存当前会完整读取文件计算摘要，损坏时明确报错，不会自动修复或自动清理旧版本/staging；这是后续可改进项。

诊断时单独改过项目 electron.exe 的完整性标签，之后已恢复 Low，最终成功不依赖该修改。没有修改全仓 ACL、关闭系统安全功能、持久重定向 TEMP 或关闭 Chromium 沙箱。正常启动时 renderer 仍为 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`。

### 运行时修好后暴露出的源码问题

| 问题 | 修复与接手注意事项 |
| --- | --- |
| ESM ready 死锁 | 顶层 await runElectron，而内部等待 app.whenReady，Electron 又等待入口求值结束。入口改为异步回调，不能改回顶层 await GUI 启动链路 |
| 窗口加载失败不易定位 | 区分主进程异常、renderer 崩溃、导航错误与 worker DB 错误，ERR_FAILED 本身不足以证明 HTML 路径错误 |
| 真实输入后保存报 VALIDATION_MALFORMED_ID | AppState 原幂等键含冒号，与 ID 契约冲突；现使用 `draft_<session>_<document>_<sequence>`。不要放宽全局 ID 校验来迁就错误格式 |
| GUI 检查通过 IPC 直存，却漏掉实际界面失败 | 新增 `gui-editor-check.mjs`，点击 Vue 按钮、调用 Electron 原生 insertText 输入 CodeMirror、触发 Ctrl+S，再经真实 IPC 读回并重载检查 |
| 直接 process.exit 截断 profile 持久化 | GUI 成功与正常退出改走 app.quit；等待保存与 worker 收尾，并区分“正在退出”和“允许最终退出”，避免重入绕过保护 |
| GUI 样本污染正常记忆 | GUI 检查按测试 DB 路径生成独立 profile，默认创建独立临时库；与正常用户作品记忆隔离 |
| npm 包装脚本吃掉 db-path | 根 gui-check:desktop 脚本补末尾 `--`，已实测参数能传给桌面启动器 |

重启验收证明数据可持久读取，未承诺界面会自动恢复“上次选中的章节”。GUI 验收使用记住的测试章节 ID 检查上次进程正文，并在页面重载后选中目标章节验证。

## 后续 agent 的工作纪律

1. 开工先读台账与本流转文档，明确用户当前授权范围。当前用户确认“全部落盘”不等于授权提交、推送、发布或变更全局安全设置。

3. 多 agent 必须先分配独占目录或文件；不要同时编辑同一文件。仓库历史要求 Lead 维护台账，其他 agent 通过消息报告。
4. 所有测试由一个持锁执行者串行组织。`tools/test-lock.mjs` acquire 到 release 期间，除持有者外任何成员不得写仓库文件，包括源码、文档和锁文件；锁被占用先协调，不删除别人的锁。
5. 维持分层：contracts/domain/application 不引入宿主依赖；renderer 不直连 SQLite，不获得任意 Node 能力；正常开发走启动器，保持默认沙箱。
6. 对 Electron 故障先区分主进程完整性、ready 时序、renderer、preload、worker 和实际业务错误。不要只重装，也不要把所有 CANTOPEN 都归因于中文路径。
7. 本机 PowerShell 的 git/curl 曾遇到 schannel 凭据错误，下载探针通过 Node fetch 完成；不要为此全局关闭 TLS 校验。当前已有依赖可直接验收，重新安装前审阅锁文件与环境。
8. 对修改跑相应行为测试，再完成必要门禁；真实编辑链路变化要重跑 GUI 与进程重启测试。只报告当前实际执行的结果，明确 Windows 开发验收与跨平台产品交付的区别。
