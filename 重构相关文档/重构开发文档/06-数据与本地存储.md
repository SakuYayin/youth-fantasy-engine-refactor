# 数据与本地存储设计

## 数据类型和标识

正文、结构、配置、任务与同步状态保存在本机 SQLite，附件独立目录，全文和向量索引为可重建派生数据。现有动态字段仍可表达，稳定 fieldId 与中文显示名分离。

实体、任务和操作 ID 使用客户端可生成的随机 UUID；revision 为不透明字符串，不比较大小或依赖设备时钟。时间使用 UTC 标准字符串，仅用于展示和审计，不用最后修改时间决定冲突胜者。同步游标是不透明字符串，超过 JS 安全整数范围也不得转换成 number。

## 逻辑数据表

下表是实现基线，SQL DDL 在 P0 根据契约生成与评审。关系约束、索引、CHECK 和迁移文件均进入版本控制。

| 表 | 关键字段与约束 |
| --- | --- |
| workspaces | id、name、schemaVersion；本地权限上下文 |
| projects | id、workspaceId、name、revision、deleted；索引 workspaceId |
| documents | id、workspaceId、projectId、kind、parentId、orderKey、title、body、revision、deleted |
| settings_entities | 稳定实体 ID、fieldSchemaId、JSON 扩展值、revision；保留未知字段 |
| relations | 工作区、两端实体、关系类型、扩展值、revision |
| assets | id、hashAlgorithm、digest、size、mime、localState、relativeKey |
| asset_refs | workspaceId、entityId、assetId；引用完整性与工作区访问 |
| revisions | entityId、revision、baseRevision、正文/结构快照或差异、sourceOpId |
| operations | opId、workspaceId、entityType、entityId、baseRevision、newRevision、payload、actor、批次 |
| outbox | opId 唯一、targetId、state、attempts、nextAttemptAt；关联持久 operation |
| sync_checkpoints | targetId、workspaceId、serverId、cursor、协议版本、最近完整同步 |
| conflicts | entityId、localRevision、remoteRevision、共同基线、双方内容、resolutionState |
| jobs | id、projectId、kind、executor、state、inputVersion、进度、租约与错误 |
| job_outputs | jobId、sequence、输出引用、完整性与采用状态 |
| plugin_data | workspaceId、pluginId、key、schemaVersion、revision、JSON 值 |
| config_values | scope、ownerId、key、schemaVersion、revision、JSON 值 |
| local_drafts | documentId、sessionId、sequence、body、baseRevision、持久状态 |

后端另有 users、sessions、devices、workspace_members、pairing_codes、remote_commands、sync_receipts、change_feed、upload_sessions 和 audit_events。数据库内部任务、令牌和审计不作为普通作品变更同步。

正文存纯文本 UTF-8，换行规范化规则版本固定；导入时保留可恢复原文。字数是业务算法的派生值，移动和桌面使用相同样本验证，不用平台字符串 length 替代中文及 Unicode 字数规则。

## 保存事务

一次 SaveDraft 用例执行：校验主体和 ProjectContext → 比较 expectedRevision → 写正文和 newRevision → 写版本记录 → 写 operation 与 outbox → 提交 → 返回本地保存成功。发布 UI 事件在事务提交后进行。写入失败不能消耗 outbox，也不能提前显示成功。

操作日志记录语义变更和新内容，初期正文按章节保存完整文本，避免自制复杂字符级 CRDT。保留共同基线后可执行三方比较。一次跨实体改动使用同一 batchId，在一个本地事务提交；网络传输不在事务内等待。

local_drafts 用于确认前恢复；编辑器序号与数据库修订分别表达 UI 和持久状态。已确认更高草稿序号后，旧回执只可被忽略，不能回写旧正文。切章等待冲刷或保留待恢复状态，不静默丢草稿。

## 数据库所有权

桌面 DB worker 独占写连接；后端也使用数据库执行器串行短事务。better-sqlite3 是首选驱动，但 Electron 与 Node ABI、平台预编译包及升级需要分别测试，不在运行时要求用户自行安装编译器。连接对象不能跨线程共享。[驱动官方仓库](https://github.com/WiseLibs/better-sqlite3)

启用 foreign_keys、WAL 和 busy_timeout，写可靠性优先评估 synchronous=FULL，并测量真实磁盘。备份使用 SQLite 在线备份机制或停服一致复制，禁止只复制主文件而遗漏活动 WAL。长查询分批或移到只读执行器，不能长期阻塞保存。

数据库必须位于设备或服务器本地可靠磁盘。NAS 作为服务器本机磁盘可用；客户端经 SMB/NFS 打开同一数据库不可用。移动端数据库参数由原生驱动适配并按相同事务样本验收。[SQLite 网络限制](https://www.sqlite.org/useovernet.html)

## 附件与恢复

逻辑资源 ID 与存储 key 分离，不在同步数据中写 Windows 绝对路径。文件先写临时区、校验大小和摘要、持久发布，再在数据库事务创建引用。跨文件系统不存在数据库与文件的一体事务，崩溃后用 staging 状态和扫描清理孤儿对象。

删除附件先删除引用并产生墓碑，实际对象 GC 等待引用、备份保留和所有有效设备游标满足条件。未知离线设备超过保留窗口后要求完整重同步，不为了节省空间立即丢掉唯一恢复版本。

磁盘满、只读权限、文件丢失和校验失败分别报错；不得把读取失败解释为空作品。损坏库和同步包隔离保存，恢复前生成报告，不自动用空白库覆盖原文件。

## 配置与秘密

用户主题、工作区模板、共享工作流与兼容插件数据使用版本化资源。窗口坐标、系统路径、权限授予为设备数据。secretRef 只在本地解析，普通备份和同步不包含模型 Key、NAS 密码、会话令牌。

秘密导出是独立、明确的加密操作，密钥恢复策略必须与备份配套；不能使用所有用户共享的固定密钥。服务端密钥材料和桌面系统密钥存储另管，不与普通插件配置混放。

## 迁移与向后兼容

schema_migrations 记录版本、校验和与执行结果，迁移前创建一致备份。迁移按单步事务执行，文件阶段使用检查点；失败不推进版本。数据版本高于程序支持范围时拒绝写入，并提供兼容导出或恢复指引。

旧版 JSON、IndexedDB 导出、sidecar、快照、世界包与同步文件分别提供只读导入器。字段映射保留旧键和未知值，保留旧 ID 或建立完整映射；正文、实体数、引用和附件摘要比较后再让用户选择切换。不得直接修改用户唯一旧库，不让新旧程序共同写同一位置。

恢复点包含数据库版本、同步协议、插件数据版本、附件清单和校验。备份恢复先在隔离目录验证，再切换服务；独立备份保留误删前版本，同步不是备份。
