### 🔴 移动端让路约束（m00632 用户明确要求，评审必查）

> 用户原话："我这个预览版的目的是为了兼容移动端，也要把移动端相关技术栈选型贴上去"

1. **分层隔离**：`contracts` / `domain` / `application` 三层**禁止 import** Electron、Node `fs`/`path`、better-sqlite3、DOM、Fastify。必须在手机原生运行时里能跑。
2. **驱动可替换**：桌面 better-sqlite3 ↔ 手机 UTS/Kotlin SQLite，共用同一套 Repository 用例与迁移语义；业务层不得直接持有 `Database` 句柄。
3. **协议共用**：同步契约桌面与移动共用（`workspaceId`/`deviceId`/`opId`/`cursor`）；手机后台用 WorkManager，**每工作区唯一任务**。

移动端原生接口已在 `packages/contracts/src/mobile/index.ts` 定义：`MobileDatabase` / `SecureStore` / `FileAccess` / `BackgroundSync` / `MobileEditorAdapter` / `MobilePlatform`（P4 填实现，P0 定契约）。

⚠️ **移动端选型暴露的两个待办（本轮未做，已登记风险 R-7/R-8）**：
- `packages/persistence-sqlite/src/schema/index.ts` 会 `export * from './open.js'`，而 `open.ts` 引入 `node:path` + `better-sqlite3` → 手机端**无法** import `@yfe/persistence-sqlite/schema` 复用 DDL。需新增「只含 DDL」子路径出口，或把 DDL 提到零依赖包。
- `saveDraft` / `repositories` 的签名绑定 `SqliteDatabase = better-sqlite3.Database` → 要真正跨端复用，需抽驱动无关接口。

### 并发纪律（用户硬性要求 m00001）

1. **一人一范围**：每个任务登记独占写入范围，范围互不重叠。共享文件（根配置、`packages/contracts/**`、本台账）**只由 Lead 写**。
2. **测试串行**：全量测试（`npm test`）同一时刻只允许一人执行，必须先用 `tools/test-lock.mjs acquire <成员名>` 取锁。
3. **包级测试用 `--project`**：`npx vitest run --project <包名>`，不触发全量。
   ⚠️ **project 名取自各包 `vitest.config.ts` 的 `test.name`**，不是 package.json 的 name。已确认可用名：`contracts`、`domain`、`persistence-sqlite`、`plugin-sdk`、`plugin-host`、`server`、`desktop`。
   ❌ 反例：`apps/desktop` 原配置漏写 `test.name`，导致 `--project desktop` 报 `No projects matched the filter "desktop"`（vitest 回退用 `@yfe/desktop`）。已修：补 `name: 'desktop'` + `root: import.meta.dirname`。
4. **写前必读**：编辑任何文件前先 `read` 最新内容；遇版本冲突重新读取再改。
5. **报告即证据**：任务完成必须附命令与输出，不接受"应该可以了"。
