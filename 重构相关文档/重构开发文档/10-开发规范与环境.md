# 开发规范与环境

## 当前与目标工程

当前仓库仍是 React/Electron 3.0.2，已有 npm 脚本和 package-lock.json。新版采用独立 apps/packages/services 入口逐步接管，先保留旧启动、旧测试和用户数据位置。文档命令分为已有命令与目标命令；不得为展示进度假造已能运行的后端或手机工程。

## 开发环境

| 工作 | 环境 |
| --- | --- |
| 桌面与后端 | Git、Node.js 24 LTS、npm；TypeScript/Vue/Vite 由 lockfile 提供 |
| Windows 原生模块 | 对应 Electron/Node 的构建工具链与预编译验证；开发机可需 C++ Build Tools，最终用户不需要 |
| macOS | macOS 构建环境与 Xcode 工具、签名和公证配置；arm64/x64 分别验证 |
| Linux | 选定基线发行版、原生模块工具链、AppImage/deb 运行依赖 |
| Android | 正式 HBuilderX、Android SDK/Platform-Tools、兼容 JDK/Gradle、签名配置和真机 |
| 容器 | 开发 Docker/Compose，发布 CI 验证 amd64/arm64 |

用户电脑已有 Java 21，但不直接认定它匹配选定 Android 工具链；按构建要求固定版本。Android Studio 尚未安装，P0 配置 SDK 和真机调试。Mac/Linux 的测试可用专用设备或 CI，但不能仅靠 Windows 编译通过宣称三平台可用。

## 版本与依赖

P0 建立版本矩阵，记录 Electron/内嵌 Node、服务器 Node、Vue、Vite、TypeScript、Cordis 来源、SQLite 驱动、HBuilderX 和原生插件。采用受维护稳定分支与精确锁文件；Cordis 属于显式风险依赖，固定来源，禁止范围自动升级。桌面内嵌 Node 与服务端 Node 并非同版本，分别运行测试。

不把 Electron 主版本越新当作稳定证据，先验证安全支持范围、回归、原生 ABI 和签名。依赖升级分批提交，可重复构建，保留锁文件与许可证。新增运行依赖需说明用途、产物增量、维护与平台支持；Rust/Wasm/连接器也是依赖成本。

## 已有与目标命令

当前已有命令：npm run dev、npm run build、npm run typecheck、npm run lint、npm test、npm run verify、npm run build:desktop。当前桌面构建脚本包含 Windows 专用处理，不作为新版跨平台构建入口照搬。

以下为 P0/P1 应实现的目标脚本，不是当前可直接执行的命令：

| 目标命令 | 作用 |
| --- | --- |
| npm ci | 固定 lockfile 安装 workspace 依赖 |
| npm run dev:desktop | Vue + Electron + 本地服务联调 |
| npm run dev:server | Fastify 与开发数据目录 |
| npm run dev:admin | Web 管理端连接开发 API |
| npm run contracts:generate | Schema、OpenAPI、TS 客户端与移动资源生成 |
| npm run contracts:check | 生成产物无漂移、样本一致 |
| npm run verify:new | 新版类型、lint、单元、契约与集成门禁 |
| npm run test:e2e | 桌面/Web 用户流程，独立临时数据目录 |
| npm run bench | 固定样本的启动、输入、保存、任务与同步基准 |
| npm run dist:desktop | 当前平台生产安装包与校验清单 |
| npm run image:server | 服务器镜像构建；多架构发布由 CI 负责 |

移动先使用正式 HBuilderX 的标准调试与 release 流程。自动打包脚本在选择云打包/离线打包方式、许可和 CI 凭据后建立，不假设 npm 能直接完成所有原生编译。

## 契约与编码规则

TypeScript strict，业务错误用稳定 code 和显式 Result/异常映射，禁止任意 any 穿过 IPC/HTTP 边界。协议 Schema 在 packages/contracts 唯一维护，生成物不能手改；先改契约、样本和兼容策略，再改实现。

时间、随机 ID、模型、文件、网络和凭据以接口注入，便于可重复故障测试。ProjectContext 显式传递，不新增可变“当前作品”服务单例。领域层不 import Electron/Vue/Fastify，也不直接读取 process.env。

数据库写入必须走 Repository 与应用用例；UI、模型工具与插件不得直接拼 SQL。事件命名与 payload 明确版本和调度语义，订阅必须返回清理方法。队列、缓存、日志和进程数设上限。

## 开发流程

每个任务形成一条可运行链路：契约/迁移 → 用例 → 宿主适配 → UI → 相关验证 → 文档。小改动不机械补重复实现的测试；保存、同步、迁移、权限和恢复必须有行为测试。新增 Schema 或数据库版本需提供迁移和回退边界。

任务记录目标、影响模块、依赖、验收、测试结果和已知限制。一个 PR 围绕可审查范围，描述具体前后行为与验证，不把生成目录数量当作交付。关键决策在[决策记录](13-决策与资料.md)更新，避免文档同时保留互相冲突的当前方案。

使用测试数据副本和独立临时数据库；开发默认不连真实用户 NAS 目录。测试密钥与用户秘密不提交仓库；分享日志前脱敏。设备连接、镜像发布、生产数据迁移和代码文档开发是不同动作，不能混同。

## 调试与故障复现

每个 IPC/HTTP 请求生成 requestId，任务追加 jobId，操作追加 opId，日志可关联但默认无正文。提供服务状态、队列、数据库版本、最近保存与同步原因的诊断页。故障复现记录应用版本、平台、协议服务版本和最小脱敏样本。

渲染异常不应让本地服务丢保存；本地服务退出后 UI 显示恢复与未确认草稿。协议调试使用临时对象，禁止用唯一远端同步包做破坏性实验。
