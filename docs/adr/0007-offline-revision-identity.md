# ADR 0007：离线修订身份与保存重放

- 日期：2026-10-15
- 状态：已采纳，随本轮全量回归验证。

旧默认生成器 `encodeRevision(revision_seq)` 使同一文档在两个离线副本上产生相同标识，即使正文完全不同。同步仅比较 revision 是否相等，这会把分叉误认为已同步。

新增可注入随机源的 `newRevision(seq, rng?)`，默认使用 UUID。桌面应用和 SQLite 默认生成器统一采用它；库内 `revision_seq` 继续负责历史排序与溢出检查。保留 `encodeRevision` 用于兼容既有数据、确定性测试；协议仍接受旧修订号，既有行不重写，不改迁移 DDL。

保存重放在归属授权后、事务版本检查前核对水位线和原正文。同序号更换正文返回 `IDEMPOTENCY_KEY_REUSED`。应用层请求账本同时记录规范化请求身份，避免同键不同载荷返回其他请求的成功结果；该字段包含正文，只能存本地，禁止输出到日志或错误。未记录请求身份的旧账本记录拒绝猜测重放。

桌面适配器将命令回执以保留类型 `application-receipt` 存在现有 operations 表，op_id 为请求键的 SHA-256，不创建 outbox 条目，不参与同步。worker 串行执行请求，并用同一事务覆盖本地用例和回执，避免实体已创建而回执落盘失败；事务内只有本地 SQL 和微任务调度，不等待网络。库结构不变。未来清理 operations 时不得删除仍需重放的命令回执。应用层按端口实例和键排队，保障同进程调用者的并发语义；跨进程原子性由适配器事务负责。

渲染层的保存键包含会话 ID、文档 ID 和草稿序号，防止重开同一文档后序号从 1 开始时复用旧键。冲突裁决会推进序号并作废旧在途请求；迟到回执不得回退新基线。

验证包括：相同内部序号的离线标识不相等、携旧版本重放、同键更换正文拒绝、真实 worker 保存与读取，以及冲突裁决后的迟到结果。
