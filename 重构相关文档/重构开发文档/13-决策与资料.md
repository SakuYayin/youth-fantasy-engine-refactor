# 技术决策与官方资料

日期：2026-10-14。本页区分用户已确认的方向、工程选择和需要 P0 锁定的实现细节。

## ADR 001 桌面采用 Electron

状态：用户已确认。支持 Windows、macOS、Linux，优先成熟编辑器与扩展生态、相对一致的 Chromium 环境、复用现有宿主经验。接受完整运行时成本，以按架构分发、依赖白名单、按需资源和性能基准控制开销。此前 Tauri 首选建议废止，Qt/Flutter 不作为当前并行实现。

Electron 稳定分支仍需安全更新和三平台验收，不承诺绝对无平台差异。现有声明 Electron 44 是旧版基线，不代表自动适合新版所有依赖。[官方介绍](https://www.electronjs.org/docs/latest)、[产品案例](https://www.electronjs.org/apps)

## ADR 002 业务使用 TypeScript 模块化单体

状态：本轮工程选择。桌面 local-service 与 Fastify 后端复用应用、任务、同步和插件模块，降低一开始同时重写 Rust/TS/Kotlin 业务的成本。Rust 不作为核心必选，CPU 热点或特殊系统需求经测量再单独引入。

后端用 Node.js 24 LTS、Fastify 5；桌面运行于 Electron 内嵌 Node，两者分别验证原生依赖。具体补丁与依赖由 P0 锁文件固定，不在设计文档虚构已安装版本。[Node LTS](https://nodejs.org/en/about/previous-releases)、[Fastify 支持政策](https://fastify.dev/docs/latest/Reference/LTS/)

## ADR 003 前端采用 Vue 3 和独立编辑器适配

状态：沿用前轮推荐。桌面与 Web 管理端共享 Vue 组件和设计令牌，uni-app x 共享概念与经验证的工具；不承诺单份 UI 覆盖全部原生与 DOM 平台。已有 React 业务界面需要逐模块迁移，不因保留 Electron 就自动复用全部 React 组件。

CodeMirror 6 为首选纯文本编辑器，隔离在 Editor Adapter 后，测试中文输入、保存与长文。富文本后续独立设计。[CodeMirror 扩展与参考](https://codemirror.net/docs/ref/)

## ADR 004 Cordis 作为生命周期内核

状态：用户已确认框架方向，具体来源和版本待 P0 固定。上游 README 明确写道："The API is not yet stable and may change without notice." 当前页面展示的 4.0.0-rc.10 是候选参考，不能将其宣传为稳定 API。DSH 使用其自有 scope 的 vendored 包，并记录本地修改；不直接把任意同名 npm 包当作完全等价实现。

通过产品 SDK、适配器、精确版本/提交、许可与完整性记录及生命周期门禁控制变化。代码包的“稳定”来自固定版本和本项目回归，不来自框架名称或 DSH 使用事实；不追随上游主分支自动更新。[Cordis 官方仓库](https://github.com/cordiverse/cordis)、[DSH vendored 清单](https://github.com/deepseek-ai/deepseek-harness/blob/master/vendor/README.md)、[生命周期概念](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-primer.md)

Cordis 不提供本产品完整权限、插件市场、移动运行时、同步和安全沙箱，这些由产品层设计。不向插件直接暴露 DSH 的会话和 Agent 结构。

## ADR 005 SQLite 与操作日志

状态：本轮工程选择。本地和单实例后端使用 SQLite，优先验证 better-sqlite3，手机使用原生事务适配。DB 执行器独占写连接，业务版本、outbox 与正文同事务，附件分阶段发布。

活数据库不放在多设备共享 SMB/NFS 目录。网络目录只作为同步对象、素材和备份。扩容需要 PostgreSQL 等时另做迁移，不先引入集群。[SQLite 网络限制](https://www.sqlite.org/useovernet.html)、[WAL](https://www.sqlite.org/wal.html)、[驱动仓库](https://github.com/WiseLibs/better-sqlite3)

## ADR 006 uni-app x 轻量 Android

状态：用户已确认。先 Android，配置/同步/远程控制/基础编辑；不开发 iOS，不直接移植全部桌面插件。优先受维护的蒸汽模式正式工具链，P0 锁定并验收原生存储与 WorkManager。

uni-app x VDOM 与蒸汽模式存在执行方式和支持矩阵差异，官方当前说明旧模式维护方向；新项目不能只依据旧版 Kotlin 编译描述选型。JS 引擎与原生渲染是两个不同维度。[官方概述](https://doc.dcloud.net.cn/uni-app-x/)、[蒸汽模式](https://doc.dcloud.net.cn/uni-app-x/app-vapor.html)、[Android 后台工作](https://developer.android.com/develop/background-work/background-tasks/persistent)

## ADR 007 同步后端可选且 API 统一

状态：用户需求。本地、局域网和远程模式共用数据与冲突规则；统一后端提供账户、设备、权限与远程命令。文件直连不伪装成具有完整中心权限管理的模式。首版不做实时多人编辑 CRDT，正文冲突保留双方版本。

SMB、FTP/FTPS、SFTP、NFS、WebDAV 和 S3 通过能力接口接入。DLNA 仅可选媒体浏览。连接器可评估 rclone，但字节复制不代替事务与冲突协议。[rclone 官方协议与能力](https://rclone.org/)

## ADR 008 首版不开放任意第三方执行

状态：发布边界。先交付内置功能插件、声明式主题模板和 SDK。第三方代码要有真实能力隔离与资源验证，不能将 Node vm、进程、Worker 当作自动沙箱；签名也不代表安全认证。

renderer 启用 contextIsolation、sandbox，禁用 Node，preload 只暴露白名单。utilityProcess 负责可信本地服务，权限由产品代理约束，不对其 Node 执行环境声称能隔离恶意插件。[Electron 安全](https://www.electronjs.org/docs/latest/tutorial/security)、[Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)

## 版本锁定记录要求

P0 在工程中形成机器可读的版本矩阵：组件、包/源码来源、精确版本/提交、完整性、许可证、支持平台、升级负责人、验证记录。Cordis 上游与 DSH fork 只能选一个明确来源；如果保留修改，单独记录补丁和升级步骤。架构决定已确认，不再重复比较桌面壳；P0 处理的是具体版本和适配可靠性。

electron-builder 使用正式文档与受维护版本；文档入口可能默认指向 next，开发时先核对版本，不把 next 当稳定发布。[构建器官网](https://www.electron.build/)
