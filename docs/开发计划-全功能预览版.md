## 4. 架构策略（决定并行度）

```
upstream schema（数据）─┐
                       ├─→ packages/schema-tabs   ← 56 个页签定义（TABS 54 ＋ editor ＋ geomaps）+ 题材包 + 解析 API（纯 TS，零宿主依赖）
题材包 packs（数据）────┘         │
                                 ▼
      apps/desktop/src/renderer/schema/          ← 目录名以本行为准（`docs/接口冻结-渲染层.md` §4 是权威所有权表）
        tab-registry.ts / TabSidebar.vue      W5 外壳：注册表 + 侧栏 + 分组 + 显隐
        TabFormView.vue  + schema-form.ts     W2 表单（9 个 form 页签）
        TabTableView.vue + schema-table.ts    W3 表格（18 个 table 页签）
        TabCardView.vue  + schema-card.ts     W4 卡片（6 个 card 页签）
        panels/                               W7 专属面板（22 个，按里程碑分批）
                                 │
                                 ▼
  纵向数据通道（Lead 独占共享文件）：
  contracts(命令/实体) → application(用例/端口) → persistence-sqlite(仓储) → db-worker IPC → renderer app-state
```

**硬规则**

1. `packages/schema-tabs` 只依赖 `@yfe/contracts`、`@yfe/domain`；禁止 Electron/Node fs/DOM/Fastify。
2. 通用渲染器是**纯展示组件**：只吃 props（元数据 + 值 + 只读位）、只发 `change`/`select` 事件，不直接调 IPC。业务接线由 Lead 在 `app-state`/tabs store 完成。
3. 页面数据统一落 `settings_entities`（`schema_template_id` + `values_json` + `order_key`），与旧版 `formData`/`cardRecords`/`tableRows` 一一对应；旧 ID 与未知字段必须保留。
4. 旧版 `order: number` 一律转 `order_key` 分数序；旧版 `portrait`/`portrait2` 等顶层字段不得静默丢弃（见迁移矩阵附录 C）。

**纪律（用户硬性要求 m00001）**：一人一文件集，禁止同时改同一文件。测试锁保护两件事：① **测试/构建串行**——`node tools/test-lock.mjs acquire <owner>` 到 `release` 期间，同一时刻只有持有者在跑 `vitest`/`tsc`/`vite build`；② **共享文件只由归属者写**——`docs/**`、根配置、`packages/contracts/**`、`app-state.ts`、`src/preload/**`、`src/main/**` 在别人持锁期间**任何人不得写**。子智能体在自己的独占文件集内**可以**在别人持锁期间继续写（写的是不相交的新文件），但不得碰共享文件、不得在别人持锁时启动测试。acquire 返回 exit 2 表示他人持锁（**绝不删锁**），轮询等待；观察到别人持锁期间有不相交新文件落盘**不构成违纪**（2026-10-15 17:04–17:08 已按此解释）。
