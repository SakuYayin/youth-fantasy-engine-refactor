## §2 建议的端口分组

### 2.1 分组原则与理由

1. **照抄本包既有范式**：`packages/tavern/src/settings.ts` 已定案「**端口作为末尾参数追加**」，不做 `createXxx(deps)` 工厂（理由见该文件 11–13 行：全部导出都是无状态纯函数，工厂只多一层闭包）。本节所有草案沿用该范式。
2. **按宿主实现体分端口，而不是按调用点分**：同一个宿主模块（`@/lib/db`、`@/lib/aiCore/*`、`@/lib/semantic/*`）能一次实现完的，合成一个端口；这样宿主侧只需写一份适配器对象，而不是 22 个文件各配一个。
3. **必须分开的三处**（理由各自独立）：
   - `TavernChatPort` 与 `TavernModelPort` 分开：前者是「发一次对话请求」，后者是「解析该用哪个模型 + 就绪判定」。测试里替身差别极大（前者桩返回文本，后者桩返回 provider 列表），合并会让 15 个调用点的测试桩都变重。
   - `TavernCapacityPort`（已存在）与 `TavernModelPort` 分开：前者在 `settings.ts` 已经冻结，且实现体是 `@/lib/ai/modelCapacity`（纯函数，宿主侧零成本直传），不是 `@/lib/ai`。
   - `TavernPlatformPort` 独立：它替掉的是 `@/lib/app/desktop` + `@/lib/sync/desktopCloudSync`，是**平台能力探测**，与存储/对话都无关，且只有 `store.ts` 一处使用。
4. **合并掉的候选**：
   - `getCurrentProjectId` / `getSetting` / `setSetting` / `getReport` / `listProjectReports` / `saveReport` / `deleteReport` / `deleteProject` / `getTableRows` / `getCardRecords` —— 全部来自 `@/lib/db`，合并进一个 `TavernStorePort`（并 `extends TavernMetaPort`）。
   - `uid` + `formatDate` —— 两个都是「一个纯函数」，合成 `TavernUtilPort`；不拆成两个接口。
   - `aiParse` 的四个函数**不设端口**（§3 建议整体复制进包）。

## §3 建议直接抄进 `packages/tavern/src/` 的纯逻辑模块
