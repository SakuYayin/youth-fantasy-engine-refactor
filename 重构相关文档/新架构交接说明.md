## 2. TypeScript 关键约束（`tsconfig.base.json`）

`strict` + `noImplicitOverride` + `noUncheckedIndexedAccess` + `noUnusedLocals` + `noUnusedParameters` +
`verbatimModuleSyntax` + `isolatedModules` + `moduleResolution: Bundler`。

- 🔴 `verbatimModuleSyntax: true` → 纯类型导入**必须**写 `import type { X } from '...'`，否则运行时报错。
- 🔴 `noUncheckedIndexedAccess: true` → `arr[0]` 类型是 `T | undefined`，必须显式判断。
- 源码内部相对导入要带 `.js` 后缀（`import { x } from './y.js'`），因为产出是 ESM。

`packages/contracts/src/errors.ts`：

```ts
export const ERROR_CODES = [...] as const   // 是【字符串字面量数组】，不是对象！
// 正确：new AppError('REVISION_CONFLICT', { message: '...' })
// 错误：ERROR_CODES.REVISION_CONFLICT   ← 不存在
new AppError(code, { message?, details?, requestId?, cause? })   // 第二参是对象，不是字符串

export function ok<T>(value: T): Ok<T>       // 🔴 成功值必须包在 value 字段里，不能平铺
```

## 6. `packages/persistence-sqlite` 内部约定

- `saveDraft(db, context, input, deps)` 已实现六步事务：
  校验主体 → 比较 expectedRevision → UPDATE 正文+新 revision → INSERT revisions →
  INSERT operations + outbox → 更新 local_drafts → 提交 → 才构造成功结果。
- `local_drafts` 同时承担「崩溃恢复缓冲」与「草稿序号水位线」，确认后**不删行**只更新
  `confirmed_revision`。删行会导致重试被当成新草稿、产生重复 operation。
- revision 是**不透明字符串**，只做相等比较，绝不 `>` 比较。
- 时间一律 UTC ISO-8601 字符串；ID 一律客户端生成 UUID。
- 新增列必须写**新的迁移**（`migrations.ts` 的 `MIGRATIONS` 数组追加），不要改 `SCHEMA_DDL` 里已有定义。

## 7. 设计文档中的硬性禁令（违反即为返工）

1. 领域层（domain/application）不得 import Electron / Vue / Fastify / SQL 驱动，不得读 `process.env`。
2. 不得新增可变的「当前作品」模块级单例 —— `ProjectContext` 必须显式传参。
3. 保存事务内**不得**等待网络；写入失败不得消耗 outbox，也不得提前显示成功。
4. 已确认更高草稿序号后，旧回执只能忽略，不能回写旧正文。
5. renderer 必须 `nodeIntegration=false`、`contextIsolation=true`、`sandbox=true`；preload 只暴露白名单 API。
6. 第三方插件只 import 产品 SDK，不得 import Cordis 或宿主私有类型。
7. 不把 `String.length` 当字数（中文/Unicode 会错），用 `@yfe/domain` 的 `countChars`。
8. 不复制旧库、不让新旧程序共同写同一位置；旧数据导入一律**只读**源文件。
