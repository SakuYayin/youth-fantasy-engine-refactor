> 目的：在「桌面端已定 Electron 44 + React 18 + TypeScript + Vite + Fastify 5 + SQLite（better-sqlite3）」的前提下，确定**移动端**技术栈，并明确**哪些代码能跨端复用、哪些必须各端重写**。

### 1.1 首选：uni-app x 蒸汽模式（Android 首发）+ UTS/Kotlin 原生 SQLite 插件

| --- | --- |
| 既定路线 | `重构相关文档/重构开发文档/03-移动端.md` 已定 uni-app x 原生渲染路线、首发只做 Android；`01-总体架构.md` 已把 `apps/mobile/` 规划为 uni-app x 与 `uni_modules` 原生适配目录 |

### 1.2 若「不允许引入第二技术栈」：PWA 只读预览（退路）

| 项 | 内容 |
| --- | --- |
| 形态 | 桌面渲染层（React 18 + Vite）产出 Web 构建，手机浏览器直接打开，只读预览作品/章节 |
| 前置条件 | **桌面渲染层目前尚未落地**：`apps/desktop` 仅有 3 个文件（`apps/desktop/src/preload/preload.mjs`、`apps/desktop/src/shared/ipc/channels.ts`、`apps/desktop/src/shared/ipc/protocol.ts`），`apps/desktop/package.json` **未声明 electron / react / vite**；根 `node_modules` 也未安装 electron / react / vue。即：PWA 退路要等 P1（单机桌面）渲染层产出后才有东西可打包 |
| 能做 | 只读取、能跑领域层（字数/排序键/合并判定都在 `@yfe/domain`）；布局自适应 |
| 不能做 | 无后台同步（浏览器无 WorkManager/BGTaskScheduler 等价物）；无原生文件系统与硬件安全存储；WebView 存储配额与「浏览器清理站点数据」风险（⚠️未核实各浏览器当前策略）；better-sqlite3 是原生模块，**不可能**在浏览器里加载（`packages/persistence-sqlite/src/schema/open.ts` 直接 `import SqliteDriver from 'better-sqlite3'`），需另写 `sql.js` / `wa-sqlite` + OPFS 适配器 |
| 定位 | **P0 的烟雾验证手段（0.5 天量级）**，不是移动端交付物（理由见 §6.1） |

### 1.3 次选与淘汰

| 候选 | 结论 | 理由（要点） |
| --- | --- | --- |
| **Capacitor 8**（+ `@capacitor-community/sqlite`） | **次选**：若要复用 Web 渲染层、且接受改既定路线，这是最稳的工程选择 | 当前稳定版 v8（官方文档页版本选择器 v9 指向 `/docs/next/…` 并明写 "This is unreleased documentation"→ v9 未发布）；`@capacitor-community/sqlite` 8.1.1（2026-09-28）成熟，但**（a）原生侧链接 SQLCipher（即使不加密）**，受美国 Encryption Export Regulations 约束、可能需提交年终 self-classification 报告；**（b）Electron 侧文档滞后**（要求 `capacitor-community/electron v5` 只能配 `Electron@25.8.4`、`node-fetch<=2.6.7`）；**（c）Android 需 Gradle JDK 21 / AGP 8.7.2 / minSdk 23 / compileSdk 35 / targetSdk 35** |

| **Flutter** | **不选** | Dart 与 TS 领域包无法共享（当前 Flutter 稳定版 3.47，官方 release notes 横幅「Flutter 3.47 is here!」/Stable releases 首条 3.47.0）。要么用 Dart 重写 `@yfe/domain`（`text`/`orderKey`/`merge` 三套算法 + `resolveConflict` 语义），要么内嵌 JS 引擎桥接——两者都直接违背本次选型的核心判据 |

## 3. 共享边界设计

### 3.1 可复用 vs 必须各端重写

| 资产 | 判定 | 依据 |
| --- | --- | --- |
| `@yfe/contracts`（全部） | ✅ **直接复用** | 无运行时依赖（`packages/contracts/package.json`）；本轮 grep：源码内无 `node:` 内置模块 import；`globalThis.crypto.randomUUID()` 在 `packages/contracts/src/ids.ts:69`（**WebView/Hermes/UTS 侧是否有该 API ⚠️未核实**，见 Q9） |
| `@yfe/domain`（全部：`text` / `orderKey` / `merge`） | ✅ **直接复用** | `packages/domain/src/index.ts:1-18` 明写「零 IO 依赖…要在桌面、后端与手机原生运行时里都能跑」；唯一依赖 `@yfe/contracts`；`Intl.Segmenter` 不可用时自动降级（`packages/domain/src/text/index.ts:112`、`:155`、`:362`） |
| `packages/persistence-sqlite/src/schema/ddl.ts` 的**纯 SQL 常量**（`SCHEMA_DDL` / `SCHEMA_MIGRATIONS_DDL` / `SCHEMA_MIGRATIONS` / 表名常量） | ✅ **可复用，但需新增「只含 DDL」的出口** | 该文件是「桌面端 SQLite Schema 的唯一权威定义」，内容为纯 SQL 字符串常量；**但** `packages/persistence-sqlite/src/schema/index.ts:25` 会 `export * from './open.js'`，而 `packages/persistence-sqlite/src/schema/open.ts:16,19` 引入 `node:path` + `better-sqlite3` → 手机端**不能** import `@yfe/persistence-sqlite/schema` |
| `saveDraft/*` 与 `repositories/*` 的**用例语义** | ⚠️ **语义要共享，签名需改造** | `packages/persistence-sqlite/src/index.ts:15` 明写「它要在桌面（better-sqlite3）与移动端（原生 SQLite）之间共享同样的用例语义」；但当前所有用例签名绑定 `SqliteDatabase = SqliteDriver.Database`（`packages/persistence-sqlite/src/schema/open.ts:28`）→ 若要复用必须抽出驱动接口（Q3） |
| 连接打开与 PRAGMA（`open.ts`） | ❌ **各端重写** | `open.ts` 直接依赖 `better-sqlite3` + `node:path`，且含进程内独占写连接登记表（`WeakRef`）；`open.ts:12` 注明「better-sqlite3 是同步驱动，连接对象只能在创建它的线程/worker 内使用」 |
| 迁移引擎（`migrator.ts`） | ❌ **各端重写**（台账算法需复刻） | `migrator.ts:29-31` 引入 `node:crypto`（sha256）、`node:fs`、`node:path`；`:526` 用 better-sqlite3 的 `transaction()`。版本闸门与 `schema_migrations` 台账格式可移植，但 checksum 计算需在 UTS/Kotlin 侧实现（保持 `sha256:` 前缀格式，见 `migrator.ts:189`） |
| 传输层（IPC / HTTP） | ❌ **各端重写** | 桌面走 `apps/desktop/src/shared/ipc/channels.ts` + `protocol.ts`；移动走 HTTP（`services/server` 的 REST，SSE 优先、不稳则带游标轮询——`01-总体架构.md`）。命令语义共用，传输实现不共用 |
| UI 视图层 | ❌ **各端重写** | 桌面 React 18（尚未落地）vs uni-app x 视图层 |
| 平台能力（`SecureStore` / `FileAccess` / `BackgroundSync` / `MobileEditorAdapter`） | ❌ **各端重写** | 契约在 `packages/contracts/src/mobile/index.ts`；实现落在 `apps/mobile/uni_modules` 的 UTS/Kotlin 插件（`01-总体架构.md` 的工程组织约定） |

### 4.3 `ddl.ts` 跨端可复用性逐条评估

被评估对象：`packages/persistence-sqlite/src/schema/ddl.ts`（613 行）。结论：**同一份 DDL 可以复用（推荐），但必须先解决出口问题，并做手机端冒烟测试**。

| # | DDL 特征 | 跨端可复用性 | 说明与风险 |
| --- | --- | --- | --- |
| A | 全部 `CREATE TABLE/INDEX ... IF NOT EXISTS`、纯 SQL 字符串常量、snake_case 列名 | ✅ 可复用 | 无方言依赖，任何 SQLite 3 均可执行 |
| B | `LATEST_SCHEMA_VERSION=1`、`SCHEMA_MIGRATIONS=[{version:1,name:'desktop-initial-schema',ddl:SCHEMA_DDL}]` | ✅ 可复用 | 迁移清单是纯数据；**已发布条目不可改**（校验和） |
| C | `schema_migrations` + 部分唯一索引 `uq_schema_migrations_applied ... WHERE success = 1`、`checksum` sha256 | ⚠️ 表结构可复用，校验和算法需在移动端复刻 | 部分索引需 SQLite ≥3.8.0（⚠️手机端实际版本未核实）；sha256 计算当前在 `migrator.ts:189` 用 `node:crypto`，移动端需 UTS/Kotlin 实现同样格式（保留 `sha256:` 前缀） |
| D | **出口耦合**：`@yfe/persistence-sqlite/schema` → `schema/index.ts:25` → `open.ts` → `node:path` + `better-sqlite3` | ❌ 当前不可直接 import | **建议**：给 `ddl.ts` 增加独立子路径出口（例如 `./schema/ddl`）或把它提到一个零依赖包；此事涉及改动 `packages/persistence-sqlite`，**超出本轮独占写入范围**，需 Lead 决定（Q2） |
| E | `*_json` 列带 `json_valid()` CHECK | ⚠️ 需实测 | 依赖 JSON1 扩展（⚠️手机端内核是否含 JSON1 未核实）→ P0 冒烟 `SELECT json_valid('{}')` |
| F | 时间列为 UTC ISO-8601 TEXT；`deleted` 用 `CHECK (deleted >= 0)`（非 0 即删除） | ✅ 可复用 | 与契约层 `isUtcTimestamp` 正则（`packages/contracts/src/ids.ts:144-148`）一致 |
| G | 实体表完整外键 + `ON DELETE CASCADE`；日志表（revisions/operations/outbox）与 `local_drafts` **刻意不建外键** | ✅ 语义可复用，但需每连接开 `PRAGMA foreign_keys=ON` | 桌面在 `open.ts` 已开；expo-sqlite 文档明说要自行执行 → 移动端必须显式执行 |
| H | 17 张表（`DESKTOP_TABLE_NAMES`）+ 10 张保留后端表名（`RESERVED_BACKEND_TABLE_NAMES`） | ✅ 可复用 | 移动端若只用子集（例如不做 jobs/plugin_data），需要**明确裁剪策略**，否则三端 schema 分叉会破坏同步（Q4） |
| I | `journal_mode=WAL` + `synchronous=full` + `busy_timeout=5000` | ⚠️ 建议对齐但需实测 | 手机上 `synchronous=full` 的写入放大/耗电需实测；`03-移动端.md` 已要求包体与缓存报告 |

### 4.4 必做的手机端 DDL 冒烟（P0 验收项）

1. 用移动端驱动执行 `SCHEMA_MIGRATIONS_DDL` + `SCHEMA_DDL`，断言 17 张表全部创建成功；
2. 断言部分唯一索引存在，且两次 `success=1` 插入被拒绝；
3. 插入一条 `*_json` 非法值，断言 `json_valid()` CHECK 生效；
4. 开事务写「正文 + revision + outbox」再回滚，断言三者都不落库；
5. 断言 `PRAGMA foreign_keys=1`、`journal_mode=wal`、字体/排序键在真机上的表现（`orderKey`）；
6. 报告 APK 下载量、安装占用与缓存占用（`03-移动端.md` 要求）。

## 5. 同步与冲突

### 5.1 弱网与后台限制（跨端硬事实）

| 平台 | 事实 | 来源 |
| --- | --- | --- |
| Android | 周期任务**最小间隔 15 分钟**（`MIN_PERIODIC_INTERVAL_MILLIS = 15 * 60 * 1000L`），flex 最小 5 分钟；受 doze/电池优化影响，源码注释明写「almost never run at this exact time」 | androidx `PeriodicWorkRequest.kt` 源码 |
| iOS | `BGTaskScheduler`（iOS 13+）用于「scheduling tasks that add background support to your app's most critical work」，含 register/submit/cancel/getPendingTaskRequests；**系统机会性调度，不能承诺准时**（具体延迟措辞⚠️未核实） | Apple 文档 `BGTaskScheduler` |
| 浏览器（PWA 退路） | 无 WorkManager/BGTaskScheduler 等价物 | — |

**结论**：任何「后台准点同步」的承诺都不成立。移动端设计原则必须是**前台可用、后台尽力**；同步进度必须能在前台一键推进（契约已给 `BackgroundSync.triggerNow`），并把「待同步条数」显式呈现（`MobileSyncState.pendingOperations`）。

### 5.2 游标与重试

| 机制 | 设计 | 证据 |
| --- | --- | --- |
| 游标 | `Cursor` 是**不透明 base36 字符串**，禁止转 number 做算术 | `packages/contracts/src/ids.ts:110-122` |
| 传输 | 首版 REST；SSE 优先，手机侧 SSE 不稳时用**带游标轮询** | `01-总体架构.md` |
| 重试 | WorkManager 每工作区唯一任务 + 指数退避 | `03-移动端.md` |
| 计量网络 | `BackgroundSync.schedule({ workspaceId, deviceId, requiresUnmetered, minIntervalMs })`；`MobileSyncState.connectivity` 区分 `online/offline/metered` | `packages/contracts/src/mobile/index.ts` |
| 事务纪律 | 写事务内**不得等网络**；正文 + revision + outbox 必须同一事务 | `packages/contracts/src/mobile/index.ts` 注释；`packages/persistence-sqlite/src/index.ts:9-15` |

### 5.3 冲突判定

| 项 | 设计 | 证据 |
| --- | --- | --- |
| 唯一裁决入口 | `resolveConflict({ baseRevision, localRevision, remoteRevision })`：`base===null`→相等则 `already-current` 否则 `fast-forward`；`local===remote`→`already-current`；`base===remote`→`fast-forward`；否则 `{kind:'conflict', reason:'diverged'}` | `packages/contracts/src/ids.ts:150-185` |
| 绝不使用时间戳 | 契约注释明确**刻意不提供基于时间戳的胜负**（设备时钟不同步会让「后写胜」变随机） | 同上 |
| 删除位（tombstone） | `resolveConflict` 看不到删除位，由领域层补齐：`isDeletedFlag` / `mergeWithoutBase` / `threeWayMerge` / `classifyFieldChange` / `divergedFields` | `packages/domain/src/merge/index.ts`（含 `:56` 对 `resolveConflict` 的再导出） |
| 时钟 | 注入式 `Clock` / `systemClock` / `fixedClock`（测试可用 `fixedClock` 造确定性场景） | `packages/contracts/src/ids.ts:129-142` |
| 落地位置 | 冲突落 `conflicts` 表（DDL 已建）；冲突/未同步数据**不得被缓存淘汰**（`canEvict` 返回 keep） | `packages/persistence-sqlite/src/schema/ddl.ts`；`packages/contracts/src/mobile/index.ts` |

### 5.4 移动端同步的最小闭环（P0/P4 里程碑）
