# 桌面架构技术调研与选型

状态更新：2026-10-14 用户已确认采用 Electron、uni-app x 与 Cordis，稳定优先。本文保留前一轮候选比较及当时建议作为历史调研，其中 Tauri/Rust/Axum 首选及对应体积目标已被替代。当前有效决策见[整体架构](整体重构架构与实施方案.md)和[重构开发文档](重构开发文档/README.md)。

调研日期：2026-10-14。依据用户重新整理的六组需求，优先级为数据可靠、使用简单、跨平台维护、轻量和性能。结论为方案建议；性能数字必须由本项目原型取得。

建议首选 **Tauri 2 稳定系列 + Vue 3 + TypeScript + Rust 本地核心 + SQLite**；移动端按已确认需求使用 uni-app x；同步后端使用 Rust/Axum，与桌面共用可移植的 Rust 业务模块。插件采用本产品 SDK 与可替换宿主，不直接把 DSH 当作桌面框架。补丁版本在原型通过后锁定，不依赖浮动 latest 发布。

## 桌面候选比较

| 候选 | 已核实的机制 | 对本项目的判断 |
| --- | --- | --- |
| Tauri 2 | Rust 宿主、系统 WebView、IPC、原生能力插件、权限能力配置；已有 2.0 稳定发布 | 首选。符合轻量与 Web 编辑器扩展目标，但需要 Rust 能力和三平台 WebView 验证 |
| Electron | 自带 Chromium 和 Node.js，支持 Windows、macOS、Linux | 保留为原型失败时的备选及旧版宿主。渲染环境较统一、现有代码复用较多，但完整运行时不利于小体积目标 |
| Wails | Go 与系统 WebView；官方主页当前提示 v3 beta，并保留 v2 入口 | Go 团队可评估稳定 v2；不以 beta v3 作为本项目首个稳定重构版本的基础 |
| Neutralinojs | 系统 WebView，内嵌静态服务与 WebSocket 原生调用 | 值得做极简工具；本项目仍需较多存储、任务、隔离和插件宿主工程，暂不优先 |
| Flutter Desktop | 支持三种桌面系统和平台插件 | 技术上可行，但引入 Dart 和另一套编辑器/UI 扩展体系，与已确定的 uni-app x 移动路线复用较少 |

机制依据：[Tauri 架构](https://v2.tauri.app/concept/architecture/)、[Tauri 稳定发布](https://v2.tauri.app/blog/tauri-20/)、[Electron 简介](https://www.electronjs.org/docs/latest)、[Wails 主页](https://wails.io/)、[Neutralino 架构](https://neutralino.js.org/docs/contributing/architecture/)、[Flutter 桌面文档](https://docs.flutter.dev/platform-integration/desktop)。适配本项目的排序属于工程判断，不能视为跨框架实测排名。

不建议从零编写窗口/WebView 框架，也不建议为追求新而直接使用预览版。可自建的是产品级插件契约、装配规则和数据能力接口；窗口、数据库、网络、线程调度和更新复用成熟组件。

## 轻量化的实际代价

Tauri 不随应用捆绑完整浏览器，具备减少分发体积的基础，但不同系统使用不同 WebView：Windows 为 WebView2，macOS 为 WKWebView，Linux 为 WebKitGTK。中文输入法、选区、拖放、字体、打印及编辑器扩展都需要各端验证。[WebView 说明](https://v2.tauri.app/reference/webview-versions/)

Windows 安装器可以安装 WebView2，也可以附带离线安装器；后者会显著增加下载体积。Linux AppImage 便于分发，但并不等于所有发行版和版本都无需兼容验证；系统库基线仍重要。macOS 发布还需要考虑签名、公证和更新流程。[Windows 安装器](https://v2.tauri.app/distribute/windows-installer/)、[Linux AppImage](https://v2.tauri.app/distribute/appimage/)、[macOS 分发](https://v2.tauri.app/distribute/)

因此必须同时报告最小应用包、常用插件完整包、首次安装依赖下载量、磁盘占用和全部应用进程内存。模型文件和运行时分别列出。不能以一个空壳的几 MB 宣称完整写作应用同样小。

初始工程目标：基础功能包压缩下载量争取不超过 40 MB（不含系统 WebView 离线安装包、可选模型和大型协议组件），目标机冷启动可编辑时间争取不超过 2 秒，空闲应用进程总内存争取不超过 200 MB。三项均为原型验证目标，完整安装成本另报；若必须引入较大的插件运行时，要重测并说明收益。

## 专用插件内核的选法

DSH 的核心价值是服务接口、依赖注入、事件、可撤销注册和配置组合；Cordis 是其服务与生命周期框架。这适合借鉴，但 DSH 的 Agent 会话模型不是本项目的作品数据库，也不能直接承担 Rust 核心或 Android 宿主。[DSH 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[Cordis 原理](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-primer.md)

建议建立产品自己的 Manifest、SDK、贡献点和能力代理。先在可信 TypeScript 界面插件中验证 Cordis：浏览器构建不能隐含依赖 Node；依赖失效、卸载清理、包体与版本稳定性必须通过原型。通过则包在 SDK 后面使用，未通过则采用同一契约的精简生命周期实现。Rust 核心使用自己的服务注册与类型接口，不强行嵌入 Node 运行时来装载 Cordis。

Tauri 原生插件由 Cargo crate 和可选 npm API 组成，适合提供文件、系统密钥、更新等能力；它不自动等于用户运行时安装任意业务插件的生态。[Tauri 插件开发](https://v2.tauri.app/develop/plugins/)

第三方纯计算插件可在后续评估 Extism/Wasm，通过宿主函数访问产品 API。Extism 提供 Manifest、内存、主机和路径配置，但宿主函数仍必须鉴权；不能把 Wasm 当作自动解决所有网络、凭据和 UI 隔离的问题。必须比较启用前后的包体、启动和内存开销，首版不强制携带。[Extism Manifest](https://extism.org/docs/concepts/manifest/)、[宿主函数](https://extism.org/docs/concepts/host-functions/)

任意第三方 JS 若直接运行在主 WebView，就可能获得该界面的权限；Worker 与单独进程本身也不等于安全沙箱。首版先开放声明式资源和可信内置扩展，第三方执行扩展在能力限制和隔离验证通过后开放。[Tauri 权限边界](https://v2.tauri.app/security/capabilities/)

## 编辑器与移动端

桌面首选验证 CodeMirror 6 的纯文本/Markdown 编辑适配，利用其扩展接口、状态事务和视口机制；小说中文输入、换行缩进、搜索和撤销仍需本项目测试。富文本作为独立能力评估，不默认安装多个完整编辑器。[CodeMirror](https://codemirror.net/6/)、[编辑视图参考](https://codemirror.net/docs/ref/#view.EditorView)

桌面和 Web 管理端采用 Vue 3，移动端采用 uni-app x，可共享设计令牌、声明式配置和通过兼容验证的纯业务工具；桌面多面板编辑器与移动基础编辑分别适配，不承诺同一套 DOM 组件在原生手机上运行。

uni-app x 最新文档已区分 VDOM 与蒸汽模式：VDOM 的 Android 代码可编译为 Kotlin；蒸汽模式业务代码可运行于 JS 引擎，UTS 原生插件保留 Kotlin 编译能力。因此不再采用“uni-app x 全部编译为 Kotlin”的笼统描述。原型分别验证构建模式、插件兼容、真实 APK、中文输入和后台恢复；锁定通过验收的正式工具链，不能只按官方渲染演示推导本项目性能。[uni-app x 概述](https://doc.dcloud.net.cn/uni-app-x/)、[蒸汽模式](https://doc.dcloud.net.cn/uni-app-x/app-vapor.html)

## 本地核心与同步后端

建议 Rust 核心与 Axum 后端组成模块化单体，复用数据契约、冲突规则、任务状态与同步模块。桌面以 Tauri IPC 调用本地应用服务；服务器以 HTTP API 调用同类服务。UI 无法直接拼 SQL 或调用任意 shell。这样既能离线，又不用在每个客户端额外启动 HTTP 服务器。[Axum](https://docs.rs/axum/latest/axum/)

Tokio 用于网络与异步任务，有界 CPU 线程池用于索引、解析和校验。异步并发与 CPU 并行分别控制；任务持久化、取消、重试和版本提交仍由产品实现。[Tokio 任务说明](https://docs.rs/tokio/latest/tokio/#cpu-bound-tasks-and-blocking-code)

SQLite 本机事务库适合第一阶段。服务器 SQLite 也放服务器本地磁盘或可靠本地卷；NAS 共享目录保存附件、同步对象和备份，不让多设备共同打开 SQLite/WAL 文件。[SQLite WAL 限制](https://www.sqlite.org/wal.html)、[网络文件系统说明](https://www.sqlite.org/useovernet.html)

WebDAV/S3 原生适配优先；SMB、FTP/FTPS、SFTP 可评估 rclone 作为按需安装的连接器，或使用逐项验证的原生库。rclone 只提供文件传输，不替代冲突与权限规则；其包体、许可、进程生命周期和凭据传递也计入评估。NFS 优先宿主机挂载后接入目录适配。[rclone 协议支持](https://rclone.org/)

## 原型决策门槛

| 原型 | 必须回答的问题 | 通过后才能确定 |
| --- | --- | --- |
| 三平台桌面 | 真实安装、冷启动、全部进程内存、中文输入、字体与文件路径是否满足目标 | Tauri 作为新版默认宿主及最低系统矩阵 |
| 插件宿主 | 三个示例插件能否启停、释放资源、保存数据，Cordis 是否适配浏览器构建 | 生命周期库与插件 SDK v1 |
| 长文与任务 | 5 千、2 万、5 万中文字符编辑，同时执行两个 AI 请求与一个索引任务 | 编辑器选择、CPU 池和并发默认值 |
| 移动端 | uni-app x 正式 APK 的基础编辑、本地缓存、同步与锁屏恢复 | 构建模式、原生能力模块和离线范围 |
| 同步与部署 | 飞牛 Compose 启动、双设备冲突、断网重试、升级保留数据、备份恢复 | 同步协议 v1 和首个可部署版本 |

如果 Tauri 在目标系统的输入法或 WebView 兼容性上存在无法合理解决的问题，再用相同工作负载比较 Electron。架构保留宿主适配接口，不同时维护两套正式桌面客户端。Rust 的学习与维护成本也是选型成本，不能只计算运行时资源。
